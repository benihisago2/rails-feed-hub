# ADR-0003: CSVインポートの部分失敗を行単位で扱う

## ステータス
承認済み / 2026-07-25

## 背景
運用者はフィードをCSVで一括登録します。数百から千行のファイルに、誤記や既登録のURLが数行混ざるのは日常的です。1行の不備が出たときに、ファイル全体をどう扱うかを決める必要がありました。

## 決定
インポート全体を包むトランザクションは張りません。行は1件ずつ独立してコミットし、弾いた行はファイル上の行番号（ヘッダを1行目と数える）・URL・理由を `error_report` に積みます。

## 検討した選択肢

**全件ロールバック** — 「全部通るか、全部戻すか」で状態が明快なのが利点。欠点は、1000行中3行の誤記で残り997行を巻き戻すこと。運用者の作業を捨てるだけで、どの3行が悪いのかも伝わりません。

**行単位処理（採用）** — 成功した行は残り、失敗した行は行番号つきで報告されます。運用者の次の作業は「3行直して再アップロード」に縮みます。欠点は、途中まで反映された中間状態が一時的に見えることです。ただしフィード登録では行同士に依存がなく、この中間状態が矛盾になることはありません。

## 根拠
トランザクションの範囲は「技術的に可能な範囲」ではなく「意味として不可分な範囲」に合わせる、というのが判断の軸です。運用者がアップロードしたCSVは、1つの不可分な取引ではなく、登録したいものの一覧です。だから単位は行になります。行同士に依存があり中間状態が矛盾を生むなら全件ロールバックが正しいのですが、フィード登録はそれに当たりません。

重複URLを「エラー」ではなく「スキップ」にしたのも同じ理由です。既登録は運用者の誤りではない。先月の一覧に数行足して投げ直すのは普通の使い方で、それを95件のエラーに数えれば、本物の誤記3件がノイズに埋もれます。スキップは上書きでもなく、既存を黙って書き換えることはしません。

## 影響
中間状態が見えるので、インポート中に記事一覧を開けば途中までの結果が映ります。行に依存関係を持つ将来の取り込み（たとえば親子構造を持つデータ）には、この方針はそのまま使えず、単位の取り直しが要ります。
